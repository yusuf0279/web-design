# Anti-repeat design check

Use this with the design pipeline on substantial sites and whenever a user says the work looks like previous designs. Its purpose is to prevent an agent from shipping the same default composition to every product.

## Inspect prior work

Check, in order:

1. Prior design-run records and screenshots in the current project.
2. Sibling projects the user explicitly names or that are clearly part of this same website-design task.
3. Other prior artifacts that are directly available in the current working context.

Do not search unrelated private directories. Do not claim to remember or have inspected a site without evidence. If there is no accessible comparison, state that. A user’s explicit “this looks like the other ones” is still actionable evidence: ask which example only if genuinely ambiguous, and continue by deliberately breaking the current fingerprint.

## Compare fingerprints

Describe both old and proposed designs using concrete choices, not vague labels such as “modern”, “clean”, or “editorial”. Compare navigation, hero, content sequence, geometry, type, color relationships, image treatment, and interaction. Note repeated combinations, since a generic card alone does not define a whole design.

Call out recognizable patterns the agent tends to reuse, including (when present) a split text-and-photo hero, small uppercase eyebrow, restrained pale background with a dark blue accent, floating metric row, uniform rounded-card grid, repeated section label/title/content stacks, and centered final CTA. These are examples to check, not a banned style list. Use a pattern only when the product’s content and task support it.

## Force a distinct design decision

For substantial work, draft three territories that change composition and information flow, not just their theme. Each should diverge from the most relevant prior work in at least five of the eight fingerprint dimensions. Preserve existing brand requirements, product conventions that genuinely help users, and content truth. For each difference, explain what product evidence justifies it.

Do not use novelty as decoration. Find a visual and structural idea in the product’s real people, objects, language, data, physical setting, or task sequence. Let that material determine the site’s signature moment, image strategy, and page rhythm. If it offers no support for a proposed flourish, remove the flourish.

## Verify in context

Compare the selected wireframe or preview with prior boards before implementation. Compare rendered screenshots after implementation when available. Check whether a stranger could identify the designs as the same template after color and copy were hidden. If yes, revisit the hero, navigation, route rhythm, and visual evidence—not merely the palette. Record the excluded patterns and the new fingerprint in the design run so later projects can avoid repeating it.
